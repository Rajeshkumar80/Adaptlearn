# REPORT_ALIGNMENT.md — Report vs. Implementation Reconciliation (Team 15)

Every feature discussed in the Team 15 report, reconciled against what was actually
built and **verified live** in this build loop. Honest by construction: nothing below
claims more than the code and the recorded curl/browser evidence prove.

Evidence style guide: `§4.x` / `§6.x` refer to the phase tasks in
`000_MASTER_PROMPT.md`; every claim listed as "Built as specified" was exercised with
real API calls or a real headless-browser session on `localhost:8001/3000`.

| Report claim (Team 15 PDF) | Status | What was actually built / why |
|---|---|---|
| Adaptive learning engine (per-student mastery) | **Built as specified** | SM-2 (stability/interval) + BKT (mastery, correct/wrong counts) per topic per student. Live-verified: wrong answer 0.2→0.129, correct 0.129→0.413 on a real topic (§4.8). |
| AI tutor with RAG over module notes | **Built as specified** | `/api/ai/ask`: embeddings search (pgvector HNSW, 384-dim) → Gemini answer with cited chunk list (file · module · similarity). Live: Waterfall/NPV questions answered with 5 citations (§4.7). |
| Follow-up MCQs after tutoring | **Built as specified (simplified)** | MCQ generated by the model per question, auto-graded, written back into BKT. Simplified to single-choice MCQ only (see formats row below). |
| **General Mode (non-VTU users)** | **Cut — deliberate** | The entire data layer (syllabus, PYQs, topics, prerequisites) is VTU-schema-seeded. General Mode would need a second ingestion path + topic graph builder — explicitly out of scope for the viva deadline; documented as future work. |
| **VTU Auto-Detection** (syllabus auto-discovery) | **Cut — deliberate** | Syllabus is ingested from the provided VTU corpus (`data/syllabus/sem5|sem6/*.md`) via a CLI (`npm run ingest`). Auto-detection of arbitrary VTU PDFs was replaced by a deterministic, reviewable ingestion pipeline; it is more reliable than auto-detection for the 11 seeded subjects. |
| **NLP topic dependency auto-extraction** | **Cut — deliberate** | Phase 2.9 scoped this to **manual/seeded prerequisites** (module structure from the syllabus + explicit prerequisite relations in seed data). Rationale: NLP extraction without a gold corpus risks wrong gates; seeded gates are correct and auditable. The gate itself is enforced server-side (403 + `blockedPrerequisites`), live-verified (§4.9). |
| **PYQ pattern analysis** (NLP question classification) | **Built differently (simplified)** | Implemented as a **frequency-based importance scorer** (`services/pyq-scorer.ts`): each topic scores by how often it appears across 2023/2024 PYQ papers per module, then normalized to 0–1 `pyqImportance` shown on roadmap/planner. Full NLP question-classification was deemed unnecessary for the demonstrated value and cut for scope. |
| **Multi-Armed Bandit for learning-method selection** | **Cut — deferred** | No bandit in the live path. Planner/scheduler ranks purely on a deterministic priority formula (§4.10/§4.11). A bandit would decide *how* to present content; our loop only decides *what* to study. Deferred — not hidden; no bandit code exists. |
| Diagram / numerical assessment formats beyond MCQ | **Cut — current limitation** | Assessment is **MCQ-only** (auto-gradable). Diagram and numerical free-input grading would require an image/numerical answer parser — cut for scope, documented in README "Honest limitations". |
| **Retention Reward (3-day-later recheck)** | **Cut — deferred** | The forgetting-curve projection exists (`/student/progress`, SM-2 retention graph) and "due for review (forgetting)" surfaces in the planner, but no automated 3-day recheck notification job was built. Deferred — infrastructure (scheduler/cron) not added. |
| **Reading-speed-based time estimation** | **Cut — deliberate** | `estimatedMinutes` is a fixed 30 min baseline; planner scales by priority, not reading speed. Measuring reading speed reliably was cut as scope creep with low viva value. |
| **RL scheduler** | **Built differently — heuristic, honestly stated** | The scheduler is a **deterministic priority formula** (low mastery + high PYQ importance + unmet prerequisites + review-due), allocating free hours proportionally — NOT a trained DQN. Planner requests persist `studyPlan` rows with the full priority breakdown, i.e. **logged trajectories that would be the training signal for a future RL version**. No RL training happened; this row intentionally does not overclaim. |
| Teacher portal (notes, assignments, class management) | **Built — new scope** | **Explicitly beyond the original report**, added deliberately to make the platform demoable end-to-end: notes upload + live chunk/embed (§4.12, browser-verified), assignments with submission/grading, classes with rosters + live socket notifications (§4.13, §6.2). |
| Anti-cheat detection in tests | **Built — new scope** | Cheat events (TAB_SWITCH etc.) recorded on test submit; teacher sees cheat report modal + integrity ledger in analytics. Live-verified with a real tab-switch flag (§4.12, §6.2 S7/S9). |
| Real-time notifications | **Built — new scope** | Socket.IO with class-scoped rooms; JWT carries `classId`, `join-class` is DB-verified server-side (bug found and fixed during §4.13: room join silently failed without `classId` in the token). |
| Analytics dashboard | **Built — new scope** | Teacher analytics: students/tests/avg-score/cheat-flag counts + score chart + integrity ledger (§4.12, §6.2 S9). |

## Deferred/cut summary (for viva — say this out loud)

> "General Mode and VTU auto-detection were cut because the whole data layer is
> VTU-seeded; NLP dependency extraction was replaced by seeded prerequisites that are
> auditable; PYQ analysis is a frequency scorer, not NLP; the bandit, 3-day retention
> job, reading-speed estimation, and non-MCQ assessment were deferred for scope. The
> scheduler is a logged heuristic — not a trained DQN — and the teacher portal is new
> scope beyond the report. Everything marked 'built' above ran live during the demo."
